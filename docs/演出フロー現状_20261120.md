# 演出フロー現状（2026-11-20）

対象は、リハーサル本番と同じ経路（20チーム・ダブルイリミネーション・2台）です。会場 Display は `FlowPresentation`、進行の正本は Worker の `event_state` と `brackets-manager` のスナップショットです。運営画面の作り込みは、この文書では「今どう見えるか」の記録に留めます。

確認材料は、当日の Display / 運営の画面（ルーザー表、台1 WINNER 残留、台2 が FINAL、運営の「この台に次の試合」）と、その時点のコードです。

## 見る人から見た一本の流れ

2台で開いたあとの会場は、だいたい次の順です。秒数は通常の `show` タイミングです。

| 順 | 会場に出るもの | 長さ | 出どころ |
|----|----------------|------|----------|
| 1 | 左右2分割。各台は呼び出し中の VS、または「次の試合を待っています」 | 操作まで | `CourtBoards` |
| 2 | 試合開始のあいだだけ全画面 VS | 約 8.5 秒（導入 3.5 + 保持 5） | spotlight `vs` |
| 3 | また2分割。試合中の台は止まった VS | 勝敗確定まで | `CourtBoards` |
| 4 | 勝敗確定のあいだだけ全画面 WINNER | 9 秒 | spotlight `winner` の前半 |
| 5 | 同じ全画面のまま、その側のトーナメント表アップ（線と写真の移動） | 6 秒 | spotlight の後半 `AnimatedBracketAdvance` |
| 6 | 2分割に戻る。確定した台は WINNER の静止画のまま | 運営が「この台に次の試合」を押すまで | `CourtBoards` が `stage === 'result'` を WinnerBoard で描く |
| 7 | 次の試合があれば、その台が呼び出し VS に替わる | — | `court-next` |

初回のルーザーズだけ、割当の前に全画面で「LOSERS」5秒 → ルーザー表 5秒が入ります（合計 10秒）。このあいだは台の割当と試合開始を止めます。

1台進行（「ゲームスタート」）は別系統です。WINNER のあとブラケット更新を挟み、次の VS へ進みます。2台進行とは画面の切り方が違います。

## ルーザー表が読めない理由

ルーザーズは、回戦ごとに「勝者が真上の1枠へ上がる回」と「横の2試合が1つに合流する回」が交互です。データ上は別の試合です。画面はそれを縦に積むので、同じ列に枠が2つ重なって見えます。

加えて、まだ下の試合が終わっていなくても、不戦勝やウィナーズからの敗者を上の枠へ先に書き込みます。`isMatchVisibleForDisplay` はルーザーズの空枠も全部出します。顔の描画は、参加者が入っている枠をそのまま2人分の柱にします。結果として、まだ誰も勝っていない段に、2チームが入った対戦カードが最初からあります。

いちばん下へ揃える処理（`baselineMatchIds`）は、フィーダーが無い試合や、下を隠した試合を「初戦と同じ段」に下ろします。ウィナーズの不戦勝を下段へ揃えるためのものです。ルーザーズにも同じ規則がかかるので、上の回戦で既に2人入っているカードが、下の空枠と同じ段に並ぶことがあります。

2026-11-20 の Display では、上に残った山と、下に「LOSERS」と書かれた横一列の二枠カードが同時に出ています。見る人には「同じ段に2チームがいる」「どの試合の結果で上がったのか分からない」状態です。前回の確認でも、3段目・4段目に最初から2チームが入っている、という指摘になっています。進行の意味（下の試合が終わるまで上は空、勝った人だけが入る）とは絵が一致していません。

消化した試合を消して残りの外接に寄せる処理（`omitCompleted` と `BracketLayoutFocus`）は、カードの中身が先に埋まっている問題は直しません。空きを詰めて大きくするだけです。

## 終盤で WINNER が残る理由

勝敗を付けると、台の状態は `result` のまま残します。全画面の WINNER と表アップは spotlight の秒数（9 + 6）が切れると終わります。そのあと2分割に戻ったとき、`CourtBoards` は `result` かつ勝者 ID がある台を、時間制限なしの WinnerBoard で描きます。

閉じる条件は「運営が次の試合を入れた」だけです。次が無いときは `court-next` が `NO_PLAYABLE_MATCH` で拒否するか、何も割り当てません。拒否されても `stage` は `result` のままなので、会場の WINNER は残ります。添付の台1（ルーザーズ 6回戦・8回戦の WINNER）が、隣で次の試合や FINAL が進んでいるあいだ消えずにいるのはこの経路です。

「次の試合が無いあいだは WINNER を閉じて待つ」処理は、2台進行にはありません。

## ファイナルが2画面のままな理由

`isFinalMatch` のコメントは「決勝は台に分けず、全画面の1試合進行へ戻す」です。この除外は、20チーム以外の台埋め（`getCourtFillMatches` のあと決勝を `waiting` から落とす枝）にだけあります。

20チーム2台は `twenty` 経路です。こちらは決勝かどうかで台を外しません。チャンピオンが出て、両方の台が空になり、ルーザー導入の秒数も終わったときだけ表彰へ進みます。それまでは `interval` のまま、`CourtBoards` が台の数（2）で列を切ります。試合が1つでも、空いた側や WINNER の側が半分を占有します。

添付では台2が FINAL の VS、台1がルーザーズ 8回戦の WINNER です。運営側も台1が「勝者確定」、台2が「試合中」の2枚です。全画面にする分岐は、この状態では動きません。

## 試合終了後に表が割り込む理由

2台進行の勝敗確定は、毎回 spotlight を1本キューします。中身は WINNER 9秒のあと、その試合の側の表アップ 6秒です。ルーザーズの試合なら `boardSide: 'losers'` の表です。spotlight は会場全体を覆うので、もう一方の台の試合中画面もその数秒は隠れます。

これに加えて、次の割り込みがあります。

- 最初のルーザーズ割当の前: LOSERS 5秒 + 表 5秒（全画面、台操作を止める）
- 運営の「会場にトーナメント表を出す」: `showBracket` が真のあいだ、台分割の代わりに表
- 20チーム以外で両方の台が空になったとき: シーンを `bracket` に戻し、約6秒の表を出してから次へ進む

「ルーザーズの試合が終わった直後に、ルーザー表のアップが数秒入る」は、spotlight 後半の仕様どおりの動作です。2台で同時に見せている最中の差し込みとしては、隣の試合を隠します。見る人からすると、勝敗のあと急に表が寄り、また2分割の WINNER に戻る、という切れ方になります。

## 運営画面が迷わせる理由（記録のみ）

運営の台カードは、状態を「空き / 呼び出し中 / 試合中 / 勝者確定」の小さいラベルで区別します。見た目の主ボタンは次のとおりです。

| 台の状態 | 主ボタン |
|----------|----------|
| 空きで次がある | 「次の試合を入れる」（押せる） |
| 空きで次が無い | 押せない待ち文言 |
| 呼び出し中 | 「試合開始」 |
| 試合中 | 勝者タップ後に勝利確定 |
| 勝者確定で演出中 | 「会場で勝者演出中…」（押せない） |
| 勝者確定で演出後 | 「この台に次の試合」（押せる・主ボタン） |

最後の行は、次の試合が実際に入るかどうかを見ていません。押せないのは「空き」のときだけです。終盤で1試合ずつしか進めないときも、終わった台の「この台に次の試合」は主ボタンのままです。押すと次が無ければ拒否されます。上の「次の試合」欄は、組める対戦が無いとき「まだ組める対戦がありません」と出しますが、台カード側のボタンは残ります。

終わった試合と進行中の試合の差は、ラベルと枠色だけです。残りの試合が1本になった、という専用の表示はありません。
