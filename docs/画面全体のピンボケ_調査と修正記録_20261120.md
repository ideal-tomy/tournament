# 画面全体のピンボケ：現象と修正の記録

記録日：2026-11-20  
対象：リハーサル会場画面  
公開先：https://tournament-through-rehearsal.pine-shaken.workers.dev  
状態：未解決。以下の3回をデプロイしたが、報告されたピンボケは残っている。

関連メモ：`docs/演出の滑らかさ・映像不具合_修正案_20261120.md`（修正前の候補一覧。項目1〜7は未着手）

## 報告された現象

会場の画面全体が、揺れているようにピンボケして見える。

- 仮画像の不具合ではない。写真を事前登録した本番相当の確認で起きる。
- 「表示を確認する」でも再現する。
- 写真が枠に入ったあと、2回戦から3回戦へ進み、その写真が次の枠に当たったタイミングで、画面全体がぼける。
- ぼけるのは枠や写真の一点ではなく、画面全体。

| 見立て | 扱い |
| --- | --- |
| 仮の顔画像（`placeholderPortrait` の「仮の画像」） | 対象外。登録済み写真でも起きる |
| 開幕ツアーの寄り | 残す。今回の修正では動かしていない |
| 紙吹雪ループ、素材の再圧縮、写真の先読み | 未着手。上記メモの項目1、3〜7 |

## 試した修正

### 1. ルーザーズ表のカメラを、同じ対象なら動かし直さない

Version：`30a849f1-0eda-4263-9c5f-84c6b62c1376`

見立て：ルーザーズ表は表示のたびに列を作り直し、`transform: none` から新しい `scale` へ 0.8 秒でアニメーションしていた。拡大のアニメーションが表全体をぼかして見せる。枠の `box-shadow` 22px もやわらかく見える。

変えたこと：

- カメラの再計算を、回戦・注目試合・進出先が変わったときだけにした（`LosersColumnBoard.tsx`）。
- 計測中の `transform` 解除を画面に出さないようにした。
- 同じ倍率なら書き戻さないようにした。
- 光る枠のぼかしを `0 0 22px` から、`0 0 0 4px` と `0 0 8px` に狭めた（`draw.css` の `losers-frame-blink`）。

結果：直らない。寄る動きが残っている、という確認。

残したもの：光る枠、中央の線が左から右へ走る演出（`losers-line-flash`）。

### 2. 寄りの拡大をやめ、位置の移動だけにする

Version：`f74a092e-fc92-4149-933a-deec3b63c677`

見立て：回戦が変わるたびに、その列へ拡大していること自体がピンボケの原因。倍率を固定し、見える位置へ動かすだけなら収まる。

変えたこと：

- ルーザーズ表の倍率を「隣り合う2列が入る大きさ」で固定し、進んでも `translate` だけ変える（`computeCamera`）。
- `.losers-track` の `transition: transform .8s` を `transition: none` にした。拡大も移動もアニメーションしない。
- 勝ち上がりでウィナーズ表に足していた CSS の `scale(zoom)`（`AnimatedBracketAdvance` の `applyTight`）を外した。6秒の溶解と、勝者が次の枠へつながる線は残した。
- ルーザーズの勝ち上がりで、1試合だけ画面いっぱいに拡大していた配置もやめた。

確認できたこと：ローカルのルーザーズ結果で、2枚の表とも `scale(0.8561)` のまま、位置だけ `translate(0px, …)` から約 `-338px` へ動いた。

結果：直らない。写真が当たったあとの 2回戦→3回戦で、画面全体がやはりピンボケする。

残したもの：光る枠、試合進行での位置移動、中央の線（左から右、0.32秒）。

### 3. ウィナーズ枠のガウスぼかしを外し、線の色をゆっくり切り替える

Version：`c7e910a9-eec9-45a1-8ca5-4491902c8d39`（いま公開中）

見立て：写真が次の枠に入る2秒目に、その枠へ SVG の `feGaussianBlur`（`#bracket-glow-strong`）が付き、CSS が1秒ごとに `filter: none` とぼかしを切り替えている。画面いっぱいの SVG が2枚重なり、両方とも同じ filter id を持つ。写真が入った瞬間に、枠だけでなく画面全体のレイヤーがぼかし越しに描かれる。

変えたこと：

- `BracketView.tsx` から `feGaussianBlur` の filter 定義を削除した。
- 試合枠と、点灯した接続線から `filter: url(#bracket-glow)` / `url(#bracket-glow-strong)` を外した。
- 代わりに、枠線の色（`#ca8a04` と `#fffef0`）と太さ（2.5 と 4）を 2.4 秒で往復させ、外側の線（`bracket-frame-halo`）の濃さも同じ周期で変えるようにした。ぼかしは使わない。

確認できたこと：ローカルの「進行」で、SVG 内の `filter` と `feGaussianBlur` は 0 件。枠線のアニメーションは `bracket-frame-line`、2.4秒、`filter: none`。

結果：直らない。

残したもの：中央の線が左から右へ走る演出。ルーザーズ枠の色の点滅（`box-shadow` は最大 8px。ガウスぼかしではない）。

## いまの画面に残っている、ぼやけに見え得るもの

今回の3回では触っていない。

- 勝ち上がりの 3〜6 秒。寄りの表と全体の表を別々に重ね、透明度を交差させる（`AnimatedBracketAdvance`）。2枚の位置や縮尺が違うと、文字や写真が二重に見える。
- ウィナーズ表は `viewBox` で今の回戦と次の回戦だけを画面いっぱいに切っている。写真はその拡大された SVG の中に入る。
- 開幕ツアーは `viewBox` を連続して書き換え、表に寄って横へ動く。
- 背景側の `blur` と `backdrop-filter`（セレモニー、VS、待機背景）。試合進行の表とは別画面。
- 会場はおおよそ1秒ごとに状態を取り直す。写真の反映とその再描画が、2回戦→3回戦の「画像が当たった」瞬間と重なる可能性はある。時間は測っていない。
