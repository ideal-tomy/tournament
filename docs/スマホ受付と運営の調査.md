# スマホ受付と大会運営の調査

2026-11-04。公開後にスマホで受付と運営を触って分かったことと、次に作り込む範囲。

会場の演出画面（ペア発表、VS、WINNER、CHAMPION）は、今回の確認としてはここまでとする。次はスマホ登録と、スマホだけで試合を進める運営画面。

## いまの位置づけ

公開先は通し確認用の Worker（`tournament-through-rehearsal`）である。受付、運営、会場 Display は同じ大会 ID（URL の `run`）を見て連動する。演出の見た目と、ボタンを押すと Display が切り替わることまでは確認できた。

運営画面そのものは、まだ「連動が壊れていないかを見る確認用」である。当日、立ったままスマホだけで進める画面にはなっていない。

## 再読み込みしないと進まない

現象は、運営画面を開いたまま待っても「試合開始」が押せない、または「次の試合へ進む」が出てこない。再読み込みすると、その時点の状態でボタンが現れる。

原因は二つある。どちらも `src/checkin/DrawControl.tsx` の状態取得にある。

### 1. 「次の試合へ進む」を画面が捨てている

サーバーは、経過時間がシーンの長さを超えると `canAdvance` を true にする。バージョン番号は変わらない。時間だけが進む。

画面は取得のたびに、次の項目が前回と同じなら描画を更新しない。

- バージョン
- 受付の改訂番号
- `canStart`（試合開始）
- `canGameStart`（ゲームスタート）

`canAdvance` はこの比較に入っていない。結果発表や表彰が終わり、サーバーが「次へ進んでよい」と返しても、画面は古い「まだだめ」の状態を持ち続ける。再読み込みは前回の状態が無いので、新しい値をそのまま表示する。

この取りこぼしはスマホに限らない。PC の運営画面でも、ほかの項目が同時に変わらなければ同じことが起きる。

### 2. 待ち時間を画面が自分で数えていない

「試合開始」「ゲームスタート」「次の試合へ進む」は、サーバーが経過時間を見て許可する。画面側に時計は無く、約 1 秒ごとの再取得で許可を知る。

その再取得は、ページが隠れているあいだは最初からスキップする。スマホでは、画面消灯、アプリの切り替え、ブラウザを後ろに回しただけでページは隠れる。戻ったときに取り直す処理もあるが、隠れたままなら何もしない。iOS は隠れたページのタイマーを止め、戻っても間隔タイマーが再開しないことがある。再読み込みだけが、止まった取得を確実にやり直す。

待ち時間の目安（通常の SHOW）は次のとおり。

| 操作 | サーバーが許可するまで |
| --- | --- |
| ゲームスタート | ブラケット表示のあと約 2 秒 |
| 試合開始 | VS のあと約 3.5 秒 |
| 次の試合へ進む（結果のあと） | 約 6 秒 |
| 次の試合へ進む（CHAMPION のあと） | 約 19 秒 |

ボタンは、許可されるまで出ないか、押せない。残り秒数は出ていないので、壊れているように見える。

## 受付から運営までの現状

1. PC で大会を 1 つ準備し、`run` 付きの URL をスマホとモニターに配る。
2. スマホの受付で名前を必須、rating と写真を任意にして登録する。写真が無いときは仮画像になる。内側カメラと外側カメラは選べる。
3. 4 名以上の偶数で受付を終了する。終了後は登録の追加、編集、削除が止まる。
4. 運営でペアを確定し、ペア発表、ゲームスタート、試合開始、勝者確定、次の試合、CHAMPION の順に進む。
5. 会場 Display は同じ状態を見て演出する。運営の操作ボタンは置かない。

受付終了は、受付画面と運営画面の両方にある。写真の保存確認に失敗している参加者は、名前だけ登録していても終了できない。

## スマホ運営画面で気になったこと

公開後の画面では、今の試合（FINAL、両チームの顔と名前、試合開始）の下に、確認用の「ペア発表 / VS / WINNER / CHAMPION」リンクが並ぶ。そのさらに下に、会場 Display を開くリンクと、縮んだブラケットがある。

スマホの幅ではブラケットの名前が読めない。次の操作ボタンは、試合カード、確認用リンク、ブラケットのあいだに埋もれる。親指で次の一手だけを押す配置ではない。

確認用の再生リンクは新しいタブを開く。当日の運営者が誤って開くと、保存済みの演出再生と、いま進んでいる試合が混ざる。

勝者の確定はブラウザの確認ダイアログである。スマホでは小さく、押し間違えたあとの戻り方も分かりにくい。

上部のナビには「開発ツール」が残っている。受付担当と運営担当に、確認用の入口が見える。

## 次に直す順

演出画面は触らない。受付と運営だけを対象にする。

### 先に直す（再読み込みがなくても進む）

- 状態を取り込むとき、`canAdvance` と経過時間も変化として扱う。許可が true になったら、再読み込みなしで「次の試合へ進む」を出す。
- ページが再び見えたら、必ず 1 回取り直す。隠れているあいだは取りにいかないままでよい。
- 試合開始とゲームスタートは、取得が遅れても残り秒が分かるようにする。サーバーの許可時刻を画面が数えるか、取得が止まったら「更新」をその場に出す。
- 運営画面の写真読み込みが失敗しても、試合を進めるボタンの更新は止めない。

### 運営画面をスマホ用にする

- 画面の下、または上に、今押せる操作だけを固定する。試合開始、勝者の 2 ボタン、次の試合、のどれか一つが常に親指の位置にある。
- 確認用の演出再生、開発ツール、読めない全体ブラケットは、運営の主画面から外す。必要なら「確認用」の奥にしまう。
- 勝者ボタンはチーム名と顔を大きくし、確認ダイアログに頼らない。
- いまの場面を一文で出す。例：「VS のあと、試合開始を押せます」「勝者を選ぶと WINNER が流れます」。

### 受付を当日用にする

- 登録、次の人、受付終了までの手数を減らす。撮った写真の確認と撮り直しを、登録ボタンの前にまとめる。
- 人数が奇数、4 名未満、写真の保存が未完了のときは、終了ボタンの横に理由を残す。運営画面へ進んだあとに初めて分かると戻れない。
- 受付終了は一箇所にする。受付担当が終了し、運営はその先だけを扱う、と役割を分ける。
- 参加者が増えたときの一覧は、名前で探せるようにする。5 秒ごとの更新は、画面に戻った瞬間にも走らせる。

## 今回は変えないもの

- 会場 Display の演出、背景、チャンピオンの光。
- 試合の勝ち上がり計算。ボタンの見た目と、許可の受け取り方だけを直す。
- 公開済みの大会データ。この文書は調査であり、進行中の試合は書き換えていない。
