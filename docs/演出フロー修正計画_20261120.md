# 演出フロー修正計画（2026-11-20）

前提は [演出フロー現状_20261120.md](./演出フロー現状_20261120.md) です。先に会場の絵と、ボタンが押せる条件を揃えます。見た目の装飾や配置の作り込みは、そのあとです。

参加者の顔と名前は、確定している人ほど大きく出します。空席や未確定の相手を、人の顔と同じ大きさの枠で埋めません。表を寄せて大きくするのは、出ている人を隠したあとの余りではなく、確定している人の周りを画面いっぱいに使うためです。

見る人の基準は次のとおりです。

1. ルーザーズにいる人は、その枠に確定した時点で顔と名前が出る。相手が未確定なら「対戦相手待ち」と分かる。
2. WINNER の演出が終わったら、会場はその台の待ちに戻る。次の試合を入れるのは運営の操作のまま。
3. 同時に見すべき試合が1つなら、台の割り当ては保ったまま、その1台を全画面にする。台番号は残す。
4. 勝者演出は確定順に1回ずつ。もう一方が呼出中・試合中なら、表のアップは出さない。
5. 次の試合が無い台の「この台に次の試合」は、会場の待ち表示と同時に押せなくする。

## 1. ルーザー表は、人を隠さず状態を分ける

表示だけを変えます。`brackets-manager` の試合結果と、次の試合の計算は変えません。ウィナーズで負けて途中の段へ入ったチームは、下のルーザーズが終わるまで待っていても、その枠の出場者です。顔を消すと「どこで誰を待つか」が分かりません。

| 状態 | 見せ方 |
|------|--------|
| 出場チームが確定済み | 顔と名前を出す。確定している人に面積を使う |
| 相手が未確定 | その側は顔の空枠にせず「対戦相手待ち」 |
| 両チーム確定・未開始 | 未開始の対戦。勝ち上がり演出は出さない |
| 実試合で勝ち上がった | 勝ち上がりの強調と移動 |
| 不戦勝で進出した | 枠には人を出す。実試合の勝利と同じ移動演出にはしない |

段の整理は、別の試合を同じ段の対戦に見せないことです。勝者がそのまま上の1枠へ入る回と、横の2試合が合流する回は、列のつながりで区別します。ウィナーズ用の下段揃え（`baselineMatchIds`）はルーザーズにはかけません。下段は、その側で最初に戦う試合です。

消化した試合を消して残りの外接に寄せる処理は残します。寄せる対象は、確定している人と「対戦相手待ち」のカードです。未確定の相手を二人分の顔枠にしないので、確定している人の写真を大きく保てます。

確認は `/venue-check` で、初期のルーザー表（途中枠に入った人が見え、相手未定は待ち文言）と、数試合消化したあとの表（勝ち上がりと不戦勝の見せ分け、顔が大きいこと）を分けます。

## 2. WINNER の終了と、次試合の割り当ては別

2台進行で勝敗が付いたあとの会場は、次の順です。

1. 全画面 WINNER。今の9秒を上限にする。台番号と、どの対戦の勝者かを出す。
2. 表のアップは、開始直前にもう一度台を見る。別の台が呼出中・試合中・VS なら出さない。両方とも結果待ちのときだけ、次の割当の前に一度見せる。
3. WINNER（と、出す場合の表アップ）が終わったら、会場のその台は待ちに戻す。静止した WINNER を、次の操作まで残さない。
4. 次の試合の割当と開始は、今どおり運営が「この台に次の試合」「試合開始」を押したときだけ行う。演出の終了では試合を入れない。
5. 最初のルーザーズ導入（タイトル5秒 + 表5秒）は、章が替わる一度だけ残す。試合ごとの表アップとは別です。

全画面 WINNER は、その9秒のあいだ隣の試合を隠します。表アップを無くしても、この割り込みは残ります。大会としてその勝利を祝う時間として残す、という判断です。

実装は spotlight の秒数が切れたあとの描画です。`stage` を運営の操作なしに `call` へ進めません。会場が待ちになることと、運営データ上の「勝者確定」は、ボタンの可否で揃えます（5）。

## 3. 1試合の全画面は、表示だけ

台への割り当て、`twenty` の段階、決勝の処理は2台進行のままです。`isFinalMatch` で1台進行のシーンへ戻しません。

- もう一方の台に、呼出済み・試合中・結果演出中の試合があるときは2分割のまま。
- もう一方に出す試合が無いときだけ、進行中の1台を全画面の VS / 試合中 / WINNER にする。
- 全画面でも「台1」「台2」は残す。参加者はどの台へ行くかを見る。
- 表彰へ進む条件（両方空き、チャンピオン確定、勝者演出が残っていない）は維持する。演出の終了だけでは表彰を始めない。

## 4. 両台の結果が続いたとき

- 勝者演出は確定した順に並べる。再生中の勝者を、別の台の結果で上書きしない。
- 各試合の勝者演出は1回だけ再生する。
- 全画面 WINNER には台番号と対戦情報を出す。
- 表アップの直前に台の状態を再確認し、別の台が呼出中・試合中になっていれば省略する。
- 最後の勝者演出が終わるまで表彰へ進まない。

## 5. 押せない操作は、会場の修正と同時に揃える

ボタンの配置や装飾は後でよいです。次の条件は、会場が待ちに戻る変更と同じ変更に含めます。

- その台に入れられる次の試合が無いときは、「この台に次の試合」を押せなくする。押すと拒否される主ボタンを残さない。
- 勝者演出の再生中は、今どおり押せなくする。
- 上の「次の試合」欄の待ち理由と、台カードのボタンは同じ条件を見る。
- 終わった台と進行中の台は、少なくとも押せる操作が違うことで区別できる。カードの見た目の作り込みは後でよい。

## 順番

1. ルーザー表の状態分けと段。確定している人の顔を大きくする。
2. WINNER 終了で会場だけ待ちに戻す。次試合は運営操作のまま。両台の演出順。
3. 出す試合が1つのときだけ、割り当てを保ったまま全画面。台番号は残す。
4. 5の操作可否を、2と同時に合わせる。
5. 確認してからリハーサルへ出す。見た目の運営 UI はそのあと。

確認は `/venue-check` の部分再生に加え、運営操作から会場まで次を通します。

- 片方の試合が長引くあいだに、もう一方の勝敗を確定する
- 両台の結果を続けて確定する（演出が上書きされない）
- 次の試合が無い（会場は待ち、ボタンは押せない、試合は増えない）
- 決勝で、もう一方に呼出が無いときは全画面、呼出があれば2分割のまま

各段階のあと、20チームの完走と台の割当の自動テストが落ちないことを確認します。表の見た目は計算の正本にしません。
