# 演出フロー修正計画（2026-11-20）

前提は [演出フロー現状_20261120.md](./演出フロー現状_20261120.md) です。先に会場で見る演出と、その秒数を決める進行を直します。運営画面のボタンや文言は、そのあと別作業にします。

見る人の基準は次の4つです。

1. ルーザー表は「下の試合が終わるまで上の枠は空。勝ったチームだけが入る」。
2. 次の試合が無い台に、WINNER を置き続けない。
3. 同時に進む試合が1つなら、その試合を全画面にする。
4. もう一方の試合が見えているあいだ、表のアップで全面を覆わない。

## 1. ルーザー表の段

表示だけを変えます。`brackets-manager` の試合結果と次の試合の計算は変えません。

- ルーザーズの各枠は、その人を送り出した試合が完了するまで空にする。不戦勝で最初から上に書かれている人も、下の対応する試合が無い場合を除き、勝敗が付くまでは顔を出さない。
- 同じ列に「2チーム入りのカード」を縦に二つ置いて、同じ段の対戦に見せない。勝者がそのまま上がる回は、行き先を一つにし、合流する回だけ横の二つの結果が揃ってから2人を描く。
- ウィナーズ用の下段揃え（`baselineMatchIds`）はルーザーズに適用しない。下段は、その側で最初に戦う試合だけにする。
- 消化試合を消してカメラを寄せる処理は残す。中身を空にしたあとの外接で大きくする。

確認は `/venue-check` に、初期のルーザー表と、数試合消化したあとのルーザー表を分ける。初期で上の段に2チームが入っていないこと、消化後も下の未消化と上の空枠の関係が追えることを見る。

## 2. 勝敗のあと、見る人に何を見せるか

2台進行の勝敗確定から次の画面までを、見る人の順で固定します。

1. 全画面 WINNER（今の9秒を上限にする。短くするならこの段階で秒数を決める）。
2. 表のアップは、もう一方の台が試合中・呼び出し中・VS のあいだは出さない。両方とも結果待ちで、次の割当前に一度だけ見せる場合に限る。
3. WINNER の秒数が終わったとき、その台に次の試合を入れられるなら呼び出しへ進む。入れられないなら WINNER を消し、待ち（空、または隣の試合だけ）にする。`result` の静止 WinnerBoard を、次の操作まで残さない。
4. 最初のルーザーズ導入（タイトル5秒 + 表5秒）は、章の切り替わりの一度だけ残す。試合ごとの表アップとは別物として扱う。

実装の芯は `court-winner` の spotlight です。`winner + bracket` を常に足さない。次が無いときの `stage: 'result'` 維持をやめるか、Display が `result` でも次試合が無い台は待ち描画にする。どちらにするかは、運営が明示的に次を押す現在の操作を壊さない方を選ぶ。会場の絵は「WINNER が残らない」で揃える。

確認は `/venue-check` に、ルーザーズ1試合の終了（表アップなしで WINNER のあと待ちに戻る）と、両方空いているときの表アップあり、を分ける。

## 3. 1試合だけのとき全画面

20チームの2台経路でも、同時に表示すべき試合が1つなら `CourtBoards` の2列にしない。

- グランドファイナル、および「もう一方に入れられる試合が無い」状態は、進行中の1試合を全画面の VS / 試合中 / WINNER にする。
- 既存の `isFinalMatch`（台に割り当てず1試合進行へ戻す）は、20チーム経路でも同じ結果になるように繋ぐ。台を2つ残したまま半分を WINNER や待ちにしない。
- 表彰へ進む条件（両方空き、チャンピオン確定）は維持する。

確認は、ルーザーズ終盤で片側だけ試合がある画面と、FINAL の画面を `/venue-check` で全画面のまま再生する。

## 4. 運営画面（演出が固まってから）

ここは実装しない。演出の項が会場で確認できてから着手する。

- 終わった台と進行中の台を、ラベル以外でも区別する（完了は主ボタンを出さない、進行中は勝敗操作だけ）。
- その台に入れられる次が無いとき、「この台に次の試合」を主ボタンにしない。上の「次の試合」欄の待ち理由と、台カードのボタンを同じ条件にする。
- 残りが1試合ずつしか進まない段階では、2台分の次試合ボタンを並べない。進行中の1台と、完了した試合の一覧が分かる形にする。

## 順番

1. ルーザー表の空枠と段（表示のみ）。
2. 勝敗後の WINNER を閉じる、試合中の表アップを止める。
3. 1試合の全画面。
4. `/venue-check` で 1〜3 を部分再生し、リハーサルへ出す。
5. 運営 UI。

各段階のあと、進行の自動テスト（20チーム完走と台の割当）が落ちないことを確認する。表の見た目は計算の正本にしない。
