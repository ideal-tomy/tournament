# 不要な確認画面・機能の削除候補

調査日：2026-11-20  
状態：コード上の調査に基づく候補一覧。削除やデプロイは行っていない。本番への影響なしを保証するには、対象確定後に依存関係と実画面の検証が必要。

## 今回の解釈と確認したい点

ホームの「演出を確認する」は `/rehearsal`（大会通しリハーサル）へ移動する。一方、ホームの「表示を確認する」は `/venue-check`（40人・20チームの仮データで各演出を開く画面）で、運営画面には別に「演出の確認」「40人の表示確認」がある。`/show-preview` は登録写真を使う演出確認画面。

「演出確認はそのまま残す」の対象が複数に解釈できるため、この一覧では `/venue-check` と `/show-preview` を保全対象として扱い、`/rehearsal` の削除も画面と機能の範囲を明示した候補とする。「演出の確認」ボタンは `/rehearsal` に接続しているため、残す対象に含むか確認が必要。

## 本番・残す演出確認のために維持するもの

- `/start`、`/checkin`、`/admin`、`/display` と、大会作成、一覧、受付、運営、会場表示、認証、写真・進行データ。
- `/venue-check` とその表示用データ・実際の演出コンポーネント。現時点で残す「演出確認」の候補として保護する。特に `/api/rehearsal/portrait-pool` を参照しているため、API を一括削除しない。
- `/show-preview` と登録写真の取得機能。残す範囲が確定するまでは保護する。
- `/api/rehearsal/config` と `/api/rehearsal/create` は名前に rehearsal があるが、`StartPage.tsx` の本番大会一覧・作成に使われている。削除不可。`main.tsx` の大会選択にも config が使われる。
- `src/lib/rehearsalTiming.ts` は本番側の進行・演出のタイミングにも参照されている。リハーサル画面と一緒に削除しない。
- ブラケット、勝者、VS、表彰などの演出コンポーネントは本番と確認画面が共有するため、確認ページを削除しても維持する。
- 保存済み大会、参加者、写真、DB・ストレージの既存データはこの整理の削除対象に含めない。

## 実施時の確認

1. 残す「演出確認」が `/venue-check`、`/show-preview`、運営の「演出の確認」（`/rehearsal`）のどれを指すか決める。
2. 対象画面の導線・直アクセス・API・共通処理を分け、既存の URL 利用とテストへの影響を確認する。残す画面へのリンクを維持する。
3. 削除後、ビルドと関連テストを実行し、大会作成・既存大会の再開、受付、運営、会場表示、指定された演出確認を実際に確認する。
4. 通し確認の自動テストを削除する場合、本番進行を検証する代替手段を確保する。不要な検証記録やデータを無条件に削除しない。
