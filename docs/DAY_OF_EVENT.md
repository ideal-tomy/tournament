# 当日運用（基本機能の目標）

**正本 URL:** https://tournament-through-rehearsal.pine-shaken.workers.dev/

この資料は、会場当日に想定する **基本フロー** と **端末の役割** を1か所にまとめたものです。UI/UX の強化はこのあと進めますが、現行 Cloudflare 版で既に動く機能の使い方を前提にしています。

## 目指す体験

| 端末 | 役割 |
|------|------|
| スマホ（参加者） | 名前・rating・写真を撮って登録。複数人を連続登録 |
| スマホ（運営） | 受付終了 → ペア発表開始 → 試合開始 → 勝者確定 など **ボタン操作** |
| 会場モニター（PC 等） | **演出だけ**表示（ペア発表・Bracket・VS・WINNER・CHAMPION）。操作 UI は置かない |

**連動の条件:** 3端末とも **同じ origin**・**同じ確認コード**・**同じ URL クエリ `?run=cf-through-...`**（大会 ID）。origin が1つでも `run` が違えば別大会です。

## 事前準備（1回だけ）

1. PC で `/rehearsal` を開き、確認コードを入力する。
2. 「実データの受付を試す（参加者0名から）」→ **新しい確認用大会を準備**（**当日は原則1回**）。
3. 表示される **「当日の3画面」** からリンクを取る（このとき URL に `run=` が付く）。
4. **会場モニター:** `③ 会場モニター` の URL を全画面で開いたままにする。
5. **参加者用:** 同じ欄の受付QR、または `① スマホ受付` の URL を配布する。
6. **運営用:** `② 運営（スマホ・PC）` を運営担当のスマホ（または PC）に開く。

資料に固定で書いてある `run=` 付き URL（`ENVIRONMENT_CONSOLIDATION.md` 等）は **過去に作った大会の例** です。当日は **必ず手順2で作った大会のリンク** だけを使ってください。Rehearsal で「準備」をもう一度押すと **別 UUID の大会** が増え、モニターとスマホがずれます。

## 当日の流れ

```text
[受付中] スマホ /checkin?run=同じ
    → 4名以上・偶数人数まで登録（写真必須）

[運営] スマホ or PC /admin?run=同じ
    → 「受付終了」 … 参加者固定・ペア自動組（サーバー側で確定）

[運営] 同じ Admin
    → 「ペア発表開始」 … 会場 Display で Draw 演出開始

[会場] /display?run=同じ
    → ペア発表 → Pair Confirmed → Bracket → VS → …（自動追従・約1秒ポーリング）

[運営] Admin
    → 「ゲームスタート」→「試合開始」→ 勝者ボタン → 「次の試合へ」… を繰り返す

[会場] Display
    → WINNER・Bracket advance・FINAL・CHAMPION を表示
```

### 自動ペア組について

運営が **「受付終了」** を押した時点で、登録済み参加者から **ペアが自動確定** されます（手で組み替える UI は現状なし）。その後 **「ペア発表開始」** で会場に演出として見せます。

### モニターに何も出ないとき

1. モニターの URL の `run=` と、受付・運営の `run=` が **完全一致**しているか。
2. モニターが **`/display`** か（`/rehearsal` や `/checkin` ではないか）。
3. 各端末で **確認コードログイン** 済みか。
4. **ペア発表開始** は Admin（運営）の操作か（受付画面からは始まらない）。

### 大会IDの確認方法

- Rehearsal の「当日の3画面」に大会IDと受付用QRが表示されます。QRは①受付専用です。QRが表示されない場合は「① スマホ受付」のURLをコピーして配布してください（QR画像は外部サービスで生成しており、受付URLだけを送ります）。
- 受付と運営の画面上部に「大会ID …末尾12文字」が出ます。会場モニターは待機表示の1行目の末尾に同じ値が出ます。3台でこの値が同じなら連動します。
- 受付・運営の画面で、存在しない大会IDやサーバーと一致しない大会IDを開くと赤い警告が出ます。その場合は Rehearsal の3リンクから開き直してください。

## 公開反映と実機チェック

公開環境へ反映する手順：

```powershell
npm test
npm run build
npm run deploy:rehearsal
```

ローカルの自動確認（別ターミナルで `npm run dev` を起動しておく）：

```powershell
$env:PLAYWRIGHT_MODULE='<Playwrightモジュールのパス>'
$env:PLAYWRIGHT_CHANNEL='msedge'
npm run test:shared-run-ux
```

実機で確認する項目：

1. PCの Rehearsal で空大会を1回だけ準備し、表示された受付QRをスマホで読み取ると `/checkin?run=...` が開く。
2. 受付・運営・モニターの大会ID末尾12文字が一致している。
3. 各端末で確認コードを入力済みで、受付で4名以上の偶数人数を写真付きで登録できる。
4. 運営で「受付終了」→「ペア発表開始」を押すと、会場モニターにペア発表演出が出る。
5. 試合開始・勝者確定の操作が会場モニターの表示に反映される。

## 現行実装との対応

| やりたいこと | 現状 |
|--------------|------|
| スマホ撮影登録 | `/checkin` |
| 自動ペア組 | 受付終了 API（`preparePairs`） |
| ボタンで演出スタート | Admin の「ペア発表開始」 |
| 運営もスマホ | `/admin` はスマホブラウザ可（UI はこれから改善） |
| モニター連動 | `/display` が `event_state` をポーリング表示 |
| 試合進行の演出 | Display 上の FlowPresentation / DrawStage |
