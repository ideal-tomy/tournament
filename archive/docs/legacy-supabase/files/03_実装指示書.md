## 0. Cursor に最初に読ませるルール

以下を `.cursor/rules/tournament.md` に配置し、常時参照させる。

```markdown
# このリポジトリの絶対ルール

1. 演出コンポーネントの中で乱数を引かない。
   抽選結果は draw_sessions に確定済み。演出はその再生のみを行う。

2. Admin から Display へ一過性の命令を送らない。
   Admin は event_state を更新するだけ。Display はそれを購読するだけ。

3. 「次の大会でこの値は変わるか？」が Yes のものをコードに書かない。
   大会名・広告・注意事項・配色はすべて DB のデータ。

4. Winners / Losers でページを分けない。同一画面のテーマを切り替える。

5. 状態を表す列に enum 型を使わない。text + CHECK 制約とする。

6. Display にいかなる操作 UI も置かない。

7. 新しいシーンを追加するときは、必ず以下 3 点をセットで実装する。
   - event_state.scene の CHECK 制約に値を追加
   - Display 側の復帰処理（リロードしても現在状態から再開）
   - Admin 側の遷移操作と、そこへ戻る操作
```

## Phase 1: シーン状態機械への置き換え

**演出を足す前に、必ずここを終わらせる。** 既存機能の作り直しであり、後からは差し込めない。

### 1-1. 状態層の実装

```
src/state/
  sceneMachine.ts      … シーン定義と遷移の妥当性判定
  useEventState.ts     … event_state を購読するフック（Display / Admin 共用）
  sceneActions.ts      … Admin 側の遷移操作（すべて event_state の update）
```

`sceneMachine.ts` の要点:

```ts
export const SCENES = [
  'idle', 'opening', 'draw', 'bracket',
  'vs_card', 'match_live', 'result', 'interval', 'award', 'finished',
] as const;

// 遷移可能な組み合わせを明示的に定義する。
// 定義外の遷移はアプリ層で弾き、ログに残す。
export const TRANSITIONS: Record<Scene, Scene[]> = { /* ... */ };
```

`useEventState.ts` の要点:

```ts
// scene_seq による順序保証。これを省略すると Realtime の順序逆転で演出が巻き戻る。
if (incoming.scene_seq <= currentSeqRef.current) return;
currentSeqRef.current = incoming.scene_seq;
```

### 1-2. Display の復帰処理

- 初期マウント時に `event_state` を 1 回フェッチし、**演出を完了状態で復元する**
- `scene_started_at` から経過時間を計算し、既に演出時間を過ぎていればアニメーションを再生せず最終フレームを描画する
- 再生途中からの復帰は実装しない（複雑さに見合わない）

### 1-3. Winners / Losers テーマ切替

```
src/theme/
  bracketTheme.ts   … bracket ごとの配色・効果音・帯文言の定数
```

```ts
export const BRACKET_THEME = {
  winners:     { accent: '#22d3ee', label: 'WINNERS',     frame: 'solid'  },
  losers:      { accent: '#f472b6', label: 'LOSERS',      frame: 'dashed' },
  grand_final: { accent: '#fbbf24', label: 'GRAND FINAL', frame: 'double' },
} as const;
```

CSS 変数に流し込み、配下のコンポーネントは変数を参照するだけにする。
`events.theme` に値があればそれで上書きする。

帯（`WINNERS ROUND 2` 等）は VS 画面・試合中画面の両方に常時表示する。

### 1-4. 起動ゲート（Display）

Display の初期画面に「開始」ボタンを 1 つ置く。クリック時に以下を行う。

1. `AudioContext` を生成して解放（ブラウザの自動再生ブロック回避）
2. `media_assets` の `preload = true` を全件プリロード
3. 進捗を画面に表示し、完了後に `idle` を描画

Admin 側にもプリロード完了率を表示する。

### 完了条件

- Display をリロードしても、現在のシーンが正しく復元される
- Winners / Losers が配色と帯で 1 秒以内に判別できる
- 音声が初回から確実に鳴る

## Phase 2: VS 演出・勝敗演出

### 2-1. 対戦カード（VS）

```
src/scenes/VsCardScene.tsx
```

- `event_state.current_match_id` の試合を表示
- `awaiting_operator = true` の間、画面隅に小さく「操作待ち」インジケーターを表示
- **自動で閉じない**。Admin の「対戦カードを閉じる」で `match_live` へ遷移

Admin 側のボタン配置（画面下部固定、押し間違い防止のため間隔を空ける）:

| ボタン | 動作 |
|---|---|
| 対戦カードを閉じる | `scene = 'match_live'` |
| 演出スキップ | 現在の演出を最終フレームへ飛ばす |
| 1 手戻す | `operation_log` の最新行を復元 |

### 2-2. 勝敗演出

```
src/scenes/ResultScene.tsx
```

GSAP タイムラインで実装する。**拡大と縮小を同時に開始しない。**

```ts
const tl = gsap.timeline();
tl.to('.stage',  { filter: 'brightness(0.35)', duration: 0.2 })
  .to('.winner', { scale: 1.5, filter: 'brightness(1.15)', duration: 0.7 }, 0.2)
  .to('.loser',  { scale: 0.75, opacity: 0.35, duration: 0.7 }, 0.5)   // 0.3秒遅らせる
  .call(playPetalOverlay, [], 1.0)
  .call(onComplete, [], 3.5);
```

**花びらは透過 WebM を 1 本重ねる。** パーティクル生成は非力な会場 PC で破綻する。
既存の透過 WebM 生成資産を流用する。

`presentation_mode = 'lite'` のとき:
- 花びら WebM → 静止画オーバーレイ
- GSAP → CSS transition
- `filter` プロパティを使わない（GPU 負荷が高い）

### 完了条件

- 更新.md 項目 1・2 の演出が意図どおり動く
- `lite` モードで低スペック機でもコマ落ちしない

## Phase 3: プレイリスト（オープニング・広告・注意事項）

**ここまで完了したら一度実運用に投入する。**

### 3-1. 汎用プレーヤー

```
src/player/PlaylistPlayer.tsx
```

`{ slot }` を受け取り、該当プレイリストを順に再生してループする。
`opening` / `interval` / `standby` / `award` のすべてで同一コンポーネントを使う。

- `media_assets.source = 'storage'` → `<video>` / `<img>` 直再生
- `media_assets.source = 'external'` → 埋め込み iframe
- 再生開始時に `ad_impressions` へ 1 行 insert
- 再生完了時に `completed = true` / `duration_ms` を update

### 3-2. オープニング

1. `events.title` / `subtitle` を差し込んだタイトル演出（テンプレは固定）
2. 続けて `slot = 'opening'` のプレイリストをループ
3. Admin が `draw` または `bracket` へ遷移させるまで回り続ける

### 3-3. Admin のメディア管理

```
src/admin/MediaManager.tsx
```

- Storage アップロード / 外部 URL 登録の両対応
- 外部 URL 登録時に「自動再生が失敗する可能性があります」と注意表示
- `is_locked = true` の項目は削除・無効化ボタンを非活性にする
- ドラッグ並べ替え（`order_no` は前後の中間値を採用）

### 完了条件

- 大会名を変えるだけでオープニングが切り替わる
- 広告を差し替えてもコードを触らない
- 注意事項が UI から消せない
- スポンサーごとの表示回数が集計できる

## Phase 4: 抽選演出 short 版 + ロック機構

### 4-1. 抽選の確定（演出より先）

```
src/draw/commitDraw.ts
```

```ts
// 1. モードに応じて組み合わせを確定
// 2. teams / team_members を作成
// 3. reveal_order を構成する
//    不変条件: 先頭から team_size 人ずつ組にすると、確定済みチームが再現される
// 4. draw_sessions に seed と reveal_order を保存し committed_at を立てる
// 5. ここまで完了してから scene = 'draw' に遷移する
```

`rating_balanced` の場合も、確定ペアが隣り合うように `reveal_order` を並べる。
**演出側は `draw_mode` を一切参照しない。**

### 4-2. short 版演出

```
src/scenes/DrawScene.tsx
```

1. 参加者カードが一斉に並ぶ
2. `reveal_order` の隣接ペアをレーザービームで結線
3. 1 チームずつ紹介
4. トーナメント表の位置へ配置

### 4-3. ロック機構

`events.status` に応じた編集可否を、**UI とアプリ層の両方**で制御する。
判定は 1 箇所に集約する。

```
src/policy/editPolicy.ts
```

```ts
export function canEdit(status: EventStatus, target: EditTarget): boolean
```

要件定義 3.5 の表をそのまま実装する。
例外的な差し替えは「修正モード」に隔離し、必ず `operation_log` に記録する。

### 完了条件

- 抽選をやり直しても演出が同じ手順で動く
- 進行中に組み合わせを編集できない
- レーティングは進行中でも編集できる


### 必須の安全装置

尺の設定値は `events.settings.draw.secPerPerson` に格納する（マイグレーション不要）。

## 付録: ディレクトリ構成（推奨）

```
src/
  state/        シーン状態機械・購読フック
  scenes/       Display の各シーン
  player/       プレイリスト再生
  theme/        bracket テーマ定数
  draw/         抽選の確定ロジック（演出を含まない）
  policy/       編集可否の判定
  admin/        Admin 画面
  display/      Display のルート・起動ゲート
  types/        database.ts（自動生成）
sql/
  00_inspect_current_schema.sql
  01_schema.sql
  02_rls_realtime.sql
  03_seed.sql
  04_reports.sql
.cursor/rules/
  tournament.md
```

`draw/` に演出コードを置かないこと。`scenes/` に乱数を置かないこと。
この 2 つが守られていれば、原則 1 は崩れない。
